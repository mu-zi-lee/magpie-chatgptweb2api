# ChatGPT Web 原生文本插件设计

设计日期：2026-10-09；2026-10-10 增加匿名模式和 Cookie 导入选项。第一版选择 TypeScript、Playwright 和 Magpie 的 Bun 宿主。

## 用户目标与范围

客户端向 Magpie 发送文本 API 请求，插件操作实际的 ChatGPT 网页（匿名或登录账号），将当前回复转换为标准 Chat Completions 响应。第一版支持文本、完整历史、段落/代码块级 SSE、取消和明确的上游错误。不需要用户部署另一个 API 服务。

MCP 不参与第一版模型请求链路。工具调用、图片、附件、网页搜索、精确 token 统计、按套餐查询额度、网页历史会话复用和完整模型自动发现留待真实网页验证。

## 架构与生命周期

```text
API 客户端 → Magpie 网关 → Bun 插件钩子
                            │ 私有 stdin/stdout JSON 管道
                            ▼
                     TypeScript worker
                            │ Playwright
                            ▼
                   专用持久浏览器配置目录
                            │ 正常网页发送/接收
                            ▼
                        chatgpt.com
```

选择 TypeScript 是为了直接使用 Playwright 和 Web Streams，减少 Go 与浏览器之间的额外绑定层。worker 使用宿主的 `process.execPath`，在 Magpie 中由 Bun 执行，开发 CLI 中由 Node 执行。它不监听端口，也不修改 Magpie 源码。

插件加载不启动浏览器。首次登录或请求时启动 worker；浏览器按账号创建，空闲后关闭进程，磁盘登录会话保留。宿主结束时私有管道关闭，worker 取消任务并关闭浏览器。每账号最多一个操作，最多同时打开四个账号配置；容量满时明确拒绝，不做后台无限排队。

## 账号与登录

提供账号和匿名两个浏览器入口。匿名模式只在未登录且可见聊天输入框时标记就绪，Cookie 和本地匿名状态保留在独立持久 profile 中；不会每次请求重新创建匿名身份。匿名 profile 后续被登录时拒绝提交，需要另建账号关联。匿名网页可用性、地区和次数限制以网页为准。

账号入口额外支持本地 Cookie 文件导入，Magpie 通过认证方法的 `prompts` 询问文件路径，CLI 通过 `login --cookies` 使用。私有管道只传路径，worker 本地读取并校验数组、`cookies` 对象或 Cookie 请求头文本。JSON 保留浏览器需要的字段，过滤非 ChatGPT 域和过期 Cookie。请求头原样保留 Cookie 值及分段令牌，使用当前主机、根路径、HTTPS 和会话期限；不从请求头推断原始有效期。读取限制为 1 MiB、512 条，文件内容、原始解析异常和 Cookie 值均不写日志。

Cookie 在新 profile 首次导航前安装，之后复用同一账号验证流程。导入成功尚未证明登录成功；必须获得用户身份和可见输入框才保存账号关联。关联不保存 Cookie 值或导出文件路径；后续请求依赖 profile，不依赖文件。Cookie 不含的 localStorage/IndexedDB 状态不会在这一入口恢复，也不人为延长 Cookie 过期时间。

Magpie 的浏览器认证 UI 使用 `auth.methods` 的 `oauth` 钩子来表达异步浏览器流程；这不是官方 OAuth 登录。登录成功返回 API 类型的本地关联 `browser:<UUID>`。Magpie 账号存储保存关联及显示用邮箱，网页 Cookie 和 session 仍保存在专用 Chromium 配置目录中，不经过网关 Authorization 请求头。

登录完成条件同时要求用户身份和网页聊天输入框可见。优先读取 `/api/auth/session`；接口无法使用时，允许从当前页面的 `client-bootstrap` JSON 中确认会话包含用户身份及非空 Access Token。成功 JSON 中的明确退出状态优先于页面旧数据。这里依据网页给出的会话状态识别登录，不在插件中解密或验证令牌签名。插件只从 session 提取身份和显示名称，不把 Access Token、Cookie 或整份 session 传给宿主。身份摘要保存在 profile marker 中；请求时发现账号更换会拒绝提交。

状态和文本请求会先等待输入框加载，再验证账号，避免页面尚未初始化时误报失效。已知浏览器验证页返回独立的 403 错误，账号关联继续保留。回复快照遇到导航造成的临时执行上下文销毁时可等待新文档并重读，仍校验原有消息身份，不重新发送提示。

浏览器配置目录属于插件自己的敏感本地状态，新增目录权限为 0700，marker 为 0600。配置不复用用户日常浏览器目录。删除 Magpie 账号只删除关联，不自动删除磁盘 profile；README 提供其位置与清理说明。

## 请求语义

内部协议只提供 `/v1/chat/completions`。其他客户端协议由 Magpie 转换，不能据此宣称完整 Responses 语义已实现。默认模型 `web-current` 明确表示网页当前选择，并非一个具体模型版本。

每请求新建页面并打开新网页对话。单条 user 文本直接发送；多轮请求以 JSON 形式保留 role/content，再附加继续最后一条用户消息的指令。网页不会提供 API 的原生 system/developer 优先级。不会将 API 历史同时重复追加到已有网页历史。

`max_tokens`、`max_completion_tokens` 只是网页提示中的近似长度偏好；采样非默认值、工具、图片、结构化输出等无法等价实现的参数会在浏览器启动前被拒绝。响应不返回估算成精确值的 usage。请求正文和回复有字符上限，私有管道和流缓存也有上限。

当前实现会创建网页对话，可能出现在网页历史；不自动删除远端会话。临时聊天的 UI 与完成条件须经真实网页核实后单独加入。

## 回复绑定与流式

发送前记录已有 `data-turn-id` / `data-message-id` 及虚拟化容器身份。新界面以 `data-turn-key` 对同组用户和助手分别保留身份，并校验回复组与提交组相同。轻量匿名界面使用 transcript 中的消息 ID、`data-assistant-markdown` 正文和 `data-message-complete` 完成标记；空的 `pending-*` 占位消息不会锁定回复身份。发送后只接受一条新的用户消息；回复只能来自这次请求之后的新助手逻辑身份。旧消息重新渲染不会被当成新回复。身份缺失、出现多个新消息、页面关闭、发送未确认均返回错误，不自动重新发送。

从渲染 HTML 转换 Markdown，排除按钮、SVG 和已知状态节点，保留段落、代码围栏、链接和表格。流中暂存最后一个未完成块，只有稳定前缀才向客户端输出。若最终网页改写了已发送内容，返回流错误，不伪造成功结束。

完成条件是本轮回复非空且停止生成，并出现本轮复制按钮，或观察到真实生成状态后输入区恢复且正文稳定。新界面中的完成按钮必须位于助手正文之后；用户消息的复制按钮不能触发完成。不能因为停止按钮尚未出现就认为生成完成。

只有明确完成才返回 `finish_reason: stop` 和 `[DONE]`。流中错误返回 error frame，非流式错误返回 HTTP 错误；部分内容不计为成功回复。客户端取消向 worker 传递 abort，尽力点击停止并关闭请求页面。网络和网页状态可能导致远端停止失败，因此不承诺取消后账号消耗为零。

## 模型与网络

第一版默认仅暴露网页当前模型。可通过 `models` 设置 exact `pickerLabel`，发送前选取并核对网页显示；找不到或无法确认时不退回其他模型。动态模型发现与嵌套菜单需要真实账号页面继续校准。

浏览器代理通过插件 `proxy` 显式设置；不声称自动继承 Magpie 的账号代理。浏览器使用真实默认配置，不加入伪装参数或验证码破解。默认以可见窗口运行；登录始终打开可见窗口。环境受限时将浏览器窗口中的状态交给用户处理。

## 验证边界

本地测试使用实际 Chromium + HTTP 网页 fixture，覆盖发送绑定、旧回复重绘、延迟生成、Markdown 增量、账号变化、失效、限流、取消、进程重启和 worker 管道。Magpie 集成测试使用未经修改的 `internal/plugin/host.js` 与 Bun，在独立临时目录中测试账号保存和 fetch 流；测试适配器仅把网页源替换为本机 fixture。

这些验证不能证明当前 chatgpt.com DOM、模型菜单、登录挑战或套餐限流行为已经兼容。真实账号试用需要用户完成专用浏览器登录，并测试普通文本、长代码块、连续请求和取消。发布前必须分别记录本地验证与真实上游结果。


## 保留窗口的浏览器生命周期

新建 profile 默认 `keep-open`：用独立 user-data-dir 启动 Chromium/Chrome/Edge，监听 loopback 随机调试端口；worker 读取该目录 DevToolsActivePort 并通过 CDP 连接默认 context。登录标签页由用户操作，文本和 doctor 新建自己的标签页，清理仅关闭请求自己的标签页。runtime 关闭及空闲回收调用 CDP browser 的断开操作，不调用默认 context.close，也不发 Browser.close。

browserMode 固定写入 profile，旧 marker 兼容 managed，避免将配置变化强加给现有 profile。窗口不再依赖 worker 生命周期；新 worker 连接仍打开的浏览器，浏览器手动关闭后按同一目录重开。启动锁带进程 PID，明确失效的启动锁可恢复；端口尚未就绪、未知锁或 profile 正由普通窗口占用时返回可重试错误，不自动关闭窗口。Google 登录拒绝与 ChatGPT 网页验证不能由本地通过测试推导为已解决。

保持窗口模式仍需要专用浏览器从一开始启用连接。现有无调试端口窗口无法原地接入；后续可评估浏览器扩展作为另一路径。账号操作新增共享 profile 文件锁和心跳；同一机器/容器的 worker 竞争返回 account_busy，正常结束释放，异常退出的过期锁 30 秒后可恢复。该实现面向本机文件系统，不作为跨服务器分布式锁。


## 首选账号入口：用户手动登录

默认且推荐的账号认证入口是手动网页登录。插件不处理密码、Google OAuth 表单或验证码，用户在专用窗口完成这些操作。只在检测到实际账号身份和可见聊天输入框后保存本地 browser:UUID；登录成功与完整文本调用分别验证。Cookie 文件导入继续保留为用户主动选择的可选入口，不用它替代手动登录验证。CLI 在等待前输出 profile UUID，登录超时可继续同一 profile；重新等待优先复用已有 ChatGPT 标签页。
