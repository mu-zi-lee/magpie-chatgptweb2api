### 真实账号 Cookie 试用

使用用户提供的本地 Cookie 请求头文本，未将内容复制进仓库或日志。专用 Chromium 导入后，当前账号页的 `client-bootstrap` 提供了用户身份和会话；旧 `/api/auth/session` 接口在这次试用中返回 403、非 JSON，因此补充页面会话识别后，CLI 实际报告登录完成并保存账号关联。

在另一个 CLI 进程中尝试“请只回复：Cookie 登录文本测试成功”，曾通过身份核对并确认网页接受用户消息，但未收到完整回复，不能算作成功文本调用。后续只读检查确认重新打开的页面返回 HTTP 403，标题为“请稍候…”，没有聊天输入框。专用窗口等待人工验证 3 分钟仍未恢复输入框，测试停止。

这证明本次 Cookie 能恢复页面账号状态，未证明账号文本桥接已可用，也不能由浏览器验证页判定 Cookie 过期。没有自动解决验证码或调整 Cookie 值来规避验证；相关请求未自动重发。导入后建立的账号 profile 保留在本机，可用于后续人工验证。

### 登录恢复改进

最后一次手动登录等待进程已终止，返回 `login_closed`；对该专用 profile 的只读 CDP 检查确认浏览器连接仍可建立，但没有标签页。没有重启或关闭该浏览器，也未将此状态误报为正在等待用户登录。
